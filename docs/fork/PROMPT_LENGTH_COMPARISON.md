# 현재 프롬프트와 짧은 프롬프트 비교

2026-09-10. **이번 짧은안은 현재안보다 품질이 낮아 교체를 권하지 않는다. 앱은 변경하지 않았다.**

## 방법

현재 구조화 프롬프트 3,405자와 502자 짧은안(약 85% 축소)을 동일 Gemma4:12b에 비교했다. 전사문 12개 × 각 안 3회 = 총 72회, 모두 정상 종료. temperature 0.3, reasoning_effort none, max_tokens 4096. 문장마다 호출 순서를 교대했다. 실제 앱의 원고 안내/escape를 사용한 비스트리밍 요청이다. STT/녹음은 제외했다. 일반 문맥 fixture이며 실제 사용 시 문맥 전체를 캡처한 실험은 아니다.

짧은안은 의미와 높임 수준, 구조화 원칙을 남기고 중복 규칙/예시/섹션을 줄였다. 지침 문구·예시·강조도 달라서 **길이만의 원인 효과를 검증한 것이 아니다.** 같은 모델에서 이 두 구체적인 프롬프트 중 무엇이 낫는지 비교한 것이다. 3회 반복을 독립적인 대규모 표본이나 통계적 유의성으로 해석하지 않는다.

## 결과

| 확인 항목 | 현재안 | 짧은안 |
|---|---:|---:|
| 반말 입력이 존댓말로 바뀜 — 실패 | 0/33회 | 5/33회 |
| 네 선택지 이름 보존 — 성공 | 3/3회 | 1/3회 |
| 진행률·재시도·주소 복사·결과 보고를 4개 작업으로 분리 — 성공 | 3/3회 | 0/3회 |
| 존댓말 요청문 형태 유지 — 성공 | 3/3회 | 0/3회 |
| 경로·1.5초·46235 보존 — 성공 | 3/3회 | 3/3회 |
| 합성 오류 제시도/하모글 → 재시도/항목 교정 — 성공 | 3/3회 | 0/3회 |

반말 시험은 11문장 × 3회=33회이고 존댓말 대조군 1문장 × 3회=3회는 별도다. 한 행의 성공이 전체 품질 합격을 뜻하지 않는다. 존댓말 요청문 형태 실패는 반말로 바뀐 것이 아니라 주요 요청을 명사형 메모로 바꾼 경우다. 선택지 보존은 단순 문자열 포함이 아니라 각각을 이름으로 유지했는지 사람이 판정했다.

짧은안의 존댓말 전환 5회는 반말 기능 질문 3회, 테스트 후 커밋 요청 2회였다. 다른 출력에서도 '~할 것', '~수행한다', 명사형 목록으로 말투가 달라졌다. multi는 4개 줄이 나와도 진행률과 재시도를 합치고 공통 제약을 작업으로 넣었으므로 4작업 분리 성공으로 세지 않았다. 내용 자체가 모두 누락됐다는 뜻은 아니다.

현재안도 단점이 있다. '말자/말고'를 '하지 마'로 바꾸며 요청 강도가 달라지는 경우가 있고, 짧은 복수 요청은 한 문장으로 남는다. 실제 사용에서는 반말→존댓말 전환이 이미 확인됐다. **이번 0/33은 그 문제의 해결이나 부재를 증명하지 않는다.** 합성 전사 오류의 교정 결과 역시 실제 STT 정확도가 아니다.

## 대표 사례

- 현재안: `... 답변을 해주는 모드야? ... 우리가 구현한 기능이야?`
- 짧은안: `... 답변을 해주는 모드인가요? ... 확인해 주세요.`

입력: `최소 깔끔하게 구조화 전문적으로 중에서 선택하게 해줘`

- 현재안: 네 선택지 이름을 모두 유지.

## 판단과 다음 단계

'프롬프트가 길어서 헷갈리니 짧게 바꾸면 해결된다'는 가설은 이번 결과로 뒷받침되지 않는다. 명시적인 높임 예시가 있는 짧은안에서도 지침을 어겼다. 그렇다고 길이는 무관하다거나 모델만이 유일한 원인이라고 단정할 수는 없다.

현재안을 유지한다. 규칙을 계속 늘리거나 지금 짧은안으로 바꾸기보다, 동일 입력·동일 프롬프트를 다른 LLM에서도 비교하여 모델의 지시 이행 차이를 분리하는 것이 다음 진단이다. 모델 교체/다운로드/앱 변경은 이번 작업에서 하지 않았다.
