# 음량 복구 후 음성 단계별 품질 평가

## 수행 내용

- 장치별 복구 수정이 이미 다른 작업에서 설치된 상태임을 확인하고 그 소스를 보존했다.
- 실제 성공 시 오류 경고 해제, 재시도 소진 후 경고 유지, 실패 이유/복구 대기 표시를 추가했다.
- 별도 워크트리 fix/audio-recovery-evaluation에 기존 Stream Deck 수정도 반영했다.
- 음량 수정은 설치·서명 검증·재시작 완료. 실제 제품 소스와 빌드 소스도 비교했다.
- 새 음성 평가 도구 및 20개 발화 세트를 만들고, 합성 음성으로 두 프롬프트를 비교했다.

## 평가 조건

macOS Yuna TTS, 16 kHz mono PCM16. 설치된 Whisper MLX large-v3-turbo worker,
로컬 Ollama gemma4:12b, temperature=0, reasoning_effort=none.
같은 WAV를 두 프롬프트에 각각 사용했고, 각 발화의 정답 전사도 각각 가공했다.
20음성 × 2프롬프트 = STT 40회, 각 STT 결과와 정답 전사에 대한 LLM 80회.
개발 15/보류 5는 기존 두 프롬프트를 비교하는 데 사용했으며 이번 결과로 프롬프트를 새로 조정하지 않았다.

installed: 설치된 빌드 소스의 Rust 프롬프트 생성기로 내보낸 structured 평가 문맥.
quality: d033d8a 작업의 기존 final/manifest.json에 보존된 revised 프롬프트.
개인 설정 전체와 앱별 장면을 반영한 실제 녹음 세션 요청은 아니다.
초기 실행에서 reasoning_effort가 빠진 평가 요청을 발견해 중단했고,
앱의 protocol.rs에 맞춰 none으로 수정한 후 처음부터 다시 실행했다.
중단된 실행은 아래 결과에 포함하지 않았다.

시간은 이번 실행의 관측값이며 성능 우열이나 지연 보장 수치로 사용하지 않는다.

### 확인된 중요한 차이

- literal: 설치 소스 프롬프트는 **정답 전사**의 ‘나중에 하기’를 ‘하기’로 줄였다.
  STT 오류가 없어도 발생하는 문구 보존 실패다. 기존 개선 프롬프트는 두 경로 모두 이름을 보존했다.
- long: 개선 프롬프트는 구현 조건과 진행 순서를 제목/항목으로 구분했다.
- steps/holdout_order: 기존 문단형 결과를 개선본이 목록으로 구성했다.
- roles: 개선본도 짧은 역할 분담/승인 조건을 문단으로 남겼다. 조건은 보존했으나 형식 개선 여지가 있다.
- holdout_correction: 개선본도 STT의 ‘3개, 아니 4개’를 그대로 남겼다.
  정답 전사의 ‘세 개, 아니 네 개’는 ‘네 개’로 정리했다. 숫자 표기에 따른 차이가 보인다.
- negative: STT가 ‘백업 파일은 그대로 둬’를 ‘백업 파일은 그대로고’로 바꾸었다.
  개선본이 이를 그대로 유지해 문장 어미 품질은 개선되지 않았다.
- holdout_english: STT가 GitHub와 개인정보 제거 구절을 잘못 인식했지만 LLM은 문맥상 복원했다.
  LLM이 항상 원래 의도를 복원할 수 있다는 뜻은 아니다.
- correction: ‘금요일이 아니라 월요일’에 대해 금요일 금지 토큰 검사가 경고했으나
  실제 의미는 올바르다. 이 경고를 의미 실패로 집계하지 않았다.

샘플별 STT/가공/정답 가공/검토 메모는 evaluation/voice/results/2026-09-11에 있다.
합성 오디오와 원본 실행 로그는 ~/.local/share/h-opentypeless/voice-eval-20260911에 있으며
개인 음성은 수집하지 않았다. 평가 스크립트 테스트 6개 통과.

## 남은 검증 및 후속 작업

- 이번 설치는 음량 경고 처리만 변경했다. 비교한 quality 프롬프트를 자동 설치하지 않았다.
- 실제 사용자 음성, 녹음/VAD/장치 전환 경로, 채팅창 포커스·붙여넣기는 아직 검사하지 않았다.
  합성 음성 20개 통과를 전체 음성 입력 기능의 통과로 표현하지 않는다.
- 다음에는 같은 20개 발화를 실제 마이크로 준비하고, 편집기와 평소 채팅창에서 최종 입력을 대조한다.
- 역할 분담과 숫자 정정을 보완할 경우, 본 사례를 회귀 세트로 옮기고 새로운 보류 사례를 추가한다.
- 알려진 심각한 의미 변형이 없더라도 실제 음성 결과와 반복 실행을 확인하기 전에는 일반적 품질을 보장하지 않는다.
