# Typeless 품질 개선 — 1차 구현

2026-09-10. 원본 `c311398`에서 Orca 자식 워크트리 `typeless-quality`, 브랜치 `HoilRyu/typeless-quality`를 만들었다. 비교 보고서를 함께 복사했다. 설치 앱·사용자 설정·원본 브랜치를 바꾸지 않았다.

## 이번 구현

- **재현 가능한 평가:** 실제 Rust 빌더의 프롬프트를 내보내고 로컬 Ollama에 같은 텍스트를 넣는 평가 도구. 모델 digest, 요청·프롬프트 hash, 종료 상태, 지연과 원본 출력을 기록한다. 출처를 표시한 16문장과 32회 비교 결과를 저장했다. [평가 안내](../../evaluation/polish/README.md)
- **기록 재다듬기:** 기록의 더보기 → ‘결과 비교·다시 다듬기’. 원문/이전 결과를 보고 네 스타일 중 하나로 다시 처리한 뒤 새 결과와 비교·복사한다. 항상 기록 ID로 DB의 원문을 가져오며 기존 기록을 덮어쓰거나 외부 앱에 자동 삽입하지 않는다. 선택문·번역·장면을 적용하지 않는 일반 받아쓰기 재처리다. 현재 AI 제공자·사전·개인 지침을 사용한다. 모델 변경은 기존 AI 설정에서 한다.
- **실패 복구:** 오류·시간 초과에도 원문과 이전 후보를 유지한다. 빈 원문/지원하지 않는 스타일/삭제된 기록을 거부한다. 중복 클릭과 동시 기록 요청을 막는다. 닫으면 결과를 버리고 자동 복사하지 않는다. 이미 시작된 요청은 최대 150초 범위에서 종료되며 닫기가 서버 취소를 뜻하지는 않는다.
- **불완전 출력 거부:** OpenAI 호환의 length/content_filter/tool_calls/function_call와 Anthropic의 max_tokens/refusal 종료 상태를 감지한다. 일부 글자가 반환됐어도 최종문으로 채택하지 않는다. 일반 받아쓰기 스트리밍에서는 검증 전 콜백을 내보내지 않는다. 종료 이유를 생략하는 기존 호환 서버는 유지한다.

## 프롬프트 판단

화행 보존 규칙을 덧붙인 후보를 기존 프롬프트와 비교했다. 자동 검사에서 후보는 16건 모두 통과했지만 Codex의 텍스트 검토에서는 메뉴 이름 훼손과 반말→존댓말 변환이 양쪽에 남았다. 후보를 기본 프롬프트에 적용할 충분한 근거가 없어 실험 자료로만 보존했다. 실험은 원음 없는 텍스트와 일반 문맥이며, Typeless 앱 비교나 STT 비교가 아니다.

## 범위와 다음 단계

이번 변경은 조사에서 제안한 첫 구현 묶음이다. STT 용어 힌트, 자동 앱 스타일, 한국어 명령 라우터, Android 계약 통일, 자동 학습은 후속 작업으로 남는다. 숫자·부정·조건의 의미 보존을 런타임 검사로 보장하지 않는다. 무조건 숫자 일치를 강제하면 ‘십오 명, 아니 오십 명’ 같은 자기 수정을 잘못 거부하므로, 실제 평가 자료에 기반해 별도로 설계한다.

한국어·영어 새 문구를 제공하며 다른 UI 언어에는 영어 문구를 사용한다. 재처리 API는 현재 H의 직접 제공자/Ollama 경로를 지원한다. 새 후보는 대화상자를 닫으면 사라지므로 필요한 결과는 복사한다. 영구 후보 저장과 오디오 재인식은 이번 범위에 포함하지 않는다.

## 검증

- Rust 라이브러리: **647 통과, 7 명시적 외부/물리 장치 시험 제외**.
- UI: **57파일, 496 테스트 통과**. 신규 재처리 4건은 원문/기존 결과 유지, 실패 후 이전 후보 유지, 중복 요청 방지, 대기 중 닫기를 검증한다.
- 평가 도구 Python 시험: **3 통과**.
- TypeScript/Vite 빌드, ESLint, Rust 라이브러리 Clippy `-D warnings`, diff 공백 검사 통과. Vite의 기존 청크 크기·혼합 import 경고는 남아 있다.
- 로컬 Gemma 평가 **32회** 완료. 모델 변경·다운로드 없음.
- 새 UI의 실제 설치 앱/OS 클립보드 실사용 및 Windows/Linux 실기기는 이번에 검증하지 않았다. 설치·병합·푸시는 하지 않았다.

## 후속 구조화 개선

영상의 입력/출력 사례를 확인한 뒤 `structured` 지침과 예시, 로컬 Ollama의 구조화 받아쓰기 생성 설정을 개선했다. 위에서 보류한 `speech-act-candidate.txt`를 그대로 적용한 변경은 아니다. 최종 30개 사례의 모델 평가와 남은 형식 차이는 [구현 기록](STRUCTURED_DICTATION_IMPLEMENTATION.md)에 정리했다.

## 2026-09-11 개발 브랜치 통합

`HoilRyu/typeless-quality`를 `feat/h-foundation-direct-providers`에 통합했다.
최신 역할 분담·숫자 정정·희망형 예시 선택 프롬프트와 Stream Deck/음량 복구 수정을 유지했다.
기록 재다듬기 API와 비교 UI, 제공자 종료 사유에 따른 불완전 출력 거부를 반영했다.
기록 재다듬기의 prompt_sha256에도 원문에 따라 선택한 희망형 예시를 포함해 실제 요청과 맞췄다.

검증: Rust 660개 통과/8개 명시적 검사 제외, UI 497개 통과, Python 평가 도구 11개 통과.
TypeScript/Vite 빌드, ESLint, 변경한 Rust 기능 파일의 형식 검사와 diff 공백 검사 통과.
전체 Python 검사에서는 기존 Whisper GGML 테스트가 시스템 Python의 NumPy 부재로 실패했다.
Vite의 기존 청크 크기 및 혼합 import 경고는 남아 있다.
프롬프트 내용은 변경하지 않아 기존 LLM 품질 평가를 다시 실행하지 않았다.
이번 작업은 소스 통합이며 설치 앱 교체와 새 UI의 실제 OS 클립보드 검증은 수행하지 않았다.
