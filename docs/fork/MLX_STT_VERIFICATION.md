# 내장 MLX 구현 및 검증

2026-09-10 · 0.1.44-beta.1 · 커밋/푸시 전 작업 상태.

## 구현

- macOS arm64 전용 Python 3.12.14 / MLX 0.31.1 / mlx-qwen3-asr 0.4.0 런타임을 앱에 포함한다. 실행 시 사용자의 Python, pip, Homebrew 또는 8765 서버에 의존하지 않는다.
- OS/실행 아키텍처와 실제 GPU 연산을 확인한다. 자동/MLX/CPU 설정을 제공하고 GPU 검사/전사 실패를 숨겨 CPU로 전환하지 않는다. CPU를 직접 선택한 경우에는 GPU 검사를 요구하지 않는다.
- Rust STT 제공자 경계와 기존 데스크톱/Ask/모바일 연결을 유지한다. LLM과 사용자 지침에는 변경이 없다.
- 녹음과 병행해 모델을 준비하고 단일 워커와 Session을 재사용한다. 작업/파일 변경은 기존 lease로 직렬화한다. 취소 중 작업은 드롭 시 종료하고, 취소 전에 준비가 끝난 캐시도 해제한다.
- 약 2분 유휴, 유휴 상태의 macOS 메모리 압박, 앱 종료/부모 사망에 워커를 정리한다. Metal 캐시 256 MiB, 메모리 예산과 wired memory 상한을 설정한다. 이는 OS 전체의 메모리 안전을 보장하는 기능은 아니다.
- 요청별 ID, 헤더/출력 64 KiB, PCM 120초 제한. Python이 임의 모델을 다운로드하지 않으며 로컬 가중치 파일 목록도 검사한다.
- 모델 가중치 카탈로그와 기존 설치 표식은 유지한다. 보조 tokenizer 파일만 별도 고정 manifest에서 검증해 추가한다. 따라서 카탈로그 표식 마이그레이션이나 가중치 재다운로드가 필요 없다.
- 앱 세션 첫 사용에 전체 해시를 검증하고 파일 식별자/크기/변경 시각이 같으면 재사용한다. Mac arm64에서는 SHA-256 하드웨어 가속을 활성화한다. 다른 플랫폼의 SHA 빌드 설정은 유지한다.

## 실제 모델 결과

Apple Silicon 32 GB Mac, 한국어 Yuna 합성 음성 세 문장. MLX는 짧은 문장 20회와 두 긴 문장을 각각 3회, CPU는 각 문장 3회 측정했다. CPU는 요청마다 로드하는 기존 엔진이고 MLX는 Session 재사용이다. 파일 캐시는 초기화하지 않았다. 아래는 엔진 호출 시간이며 해시·LLM·텍스트 출력은 제외한다.

| 모델 | 문장 | MLX 중앙값 | CPU 중앙값 |
|---|---|---:|---:|
| Qwen 1.7B | 짧음 | 0.280초 | 2.724초 |
| Qwen 1.7B | 중간 | 0.818초 | 4.339초 |
| Qwen 1.7B | 김 | 1.352초 | 7.180초 |
| Qwen 0.6B | 짧음 | 0.144초 | 0.793초 |
| Qwen 0.6B | 중간 | 0.410초 | 1.791초 |
| Qwen 0.6B | 김 | 0.675초 | 2.871초 |

세 문장에서 각 모델의 CPU/MLX 결과가 동일했다. 1.7B의 ‘취소→최소’, 0.6B 긴 문장의 일부 오인식도 양쪽에 동일하게 남았다. 이 검사는 일반 음성 정확도 평가나 실제 마이크 검증을 대체하지 않는다.

1.7B 짧은 문장 반복 시 MLX active memory는 4,082,285,914바이트로 일정했고, 독립 워커는 120.6초 유휴 뒤 종료됐다. 120초 PCM 입력도 약 10.3초에 완료됐다. 부모가 유휴/모델 작업 도중 종료되는 경우 모두 워커 종료/회수를 확인했다.

Rust 제공자 실제 경로: 첫 호출 18.8초에서 ARM 체크섬 가속 후 4.75초로 감소, 이후 0.31초 수준. 최초 파일 검증을 포함하며 LLM/출력은 제외한다. 시스템 부하에 따라 달라지는 단일 실행 묶음이다.

## 설치본과 자동 검사

최종 서명 앱을 `/Applications/H-OpenTypeless.app`에 설치했다. UI에서 자동 → MLX, 기존 Qwen 1.7B 선택, 메모리 해제 후 대기 상태를 확인했다. 키체인 helper의 SHA-256과 서명은 유지했다.

설치본 모바일 API에서 같은 합성 음성 요청을 세 번 실행했다. MLX 전사와 기존 Ollama 다듬기를 포함해 4.805초 / 0.907초 / 0.917초였고 warning은 없었다. 최초 측정은 앱 세션의 첫 요청이며 컴퓨터 재부팅 후 완전한 cold-cache 측정은 아니다. Android 실기기와 실제 마이크 재검증은 이 측정에 포함되지 않는다.

UI 472개, Rust 643개 통과. 기본 Rust 실행의 ignored 5개 중 MLX 실제 제공자 검사는 별도 실행해 통과했다. Clippy `--lib -- -D warnings` 및 릴리즈 스크립트 테스트 10개 통과. 기존 모델의 다운로드/전사 ignored 테스트를 모두 다시 실행했다는 의미는 아니다.

검증용 DMG(119.0 MiB)를 생성했다. 읽기 전용으로 마운트한 DMG 내부에서 앱 서명, Applications 드래그 대상, 번들 GPU probe를 검사해 통과했다. 실제 공개 릴리즈, 커밋과 푸시는 하지 않았다.

## 재현 자료

- `tools/diagnostics/check_mlx_stt.py`: 합성 음성 CPU/MLX 비교 및 선택적 유휴 종료 검사.
- `tools/diagnostics/check_mlx_parent_exit.py`: 부모 프로세스 종료 시 워커 회수 검사.
- Rust ignored 테스트 `real_mlx_provider_reuses_and_releases_model`: 실제 제공자의 준비/전사/재사용/취소.
- 로컬 결과: `~/.local/share/h-opentypeless/mlx-build/{repeated-benchmark,benchmark-0.6b,limit-benchmark,installed-mobile-final}.json`.

## 한계와 후속

macOS 14용 wheel을 고정했으나 macOS 14 실기기는 검증하지 않았다. 현재 Mac에서 서명된 번들을 사용자의 Python/Homebrew가 없는 PATH로 검사했다. Windows/Linux 실기기 검증은 예정대로 후속이며 해당 플랫폼에 MLX GPU 지원을 표시하지 않는다.

MLX 실패 시 현재 오류 경로로 안내하고 설정에서 CPU를 선택한 뒤 다시 녹음할 수 있다. 실패 음성을 별도 UI에 보관해 즉시 재전사하는 기능은 이번 변경에 추가하지 않았다. 모델 준비/작업 상태는 설정에서 표시하며 별도 튜토리얼은 다음 작업이다.
