# 녹음 중 출력 음량 조절

## 동작

설정 → 일반 → 녹음 중 다른 소리. 끄기(기본값), 소리 줄이기(기존 출력 음량 값의 0~100%, 기본20%), 음소거. 슬라이더 또는 숫자 입력으로 비율을 지정한다. 숫자는 Enter/입력칸 벗어나기, 슬라이더는 조작 완료 시 저장한다. 0%는 출력 음량0, 100%는 변경 없음이다. 기존 비율 없는 설정은20%로 읽는다. 포크 전용 설정으로 저장하며 다음 녹음부터 적용한다. 유튜브/음악 재생 자체는 멈추지 않는다. 마이크 입력 음량은 바꾸지 않는다.

일반 받아쓰기·번역과 Ask의 실제 마이크 시작 전 적용하고, 오디오 캡처가 끝나면 STT/LLM 완료를 기다리지 않고 복원한다. 시작 실패·취소·정상 종료도 복원한다. 각 녹음 경로의 시작/종료를 구분하여 다른 경로의 종료가 진행 중인 녹음의 음량을 복원하지 않게 한다.

출력 장치가 바뀌면 이전 장치를 복원하고 새 장치를 조절한다. 한 녹음에서 같은 장치는 한 번만 낮춘다. 지원하지 않는 장치나 오디오 서버 오류는 경고로 남기고 녹음은 계속한다.

## 사용자 조작과 복구

원래 음량·음소거 상태와 앱이 적용한 값을 장치의 안정된 식별자와 함께 기록한다. 복원할 때 앱이 바꾼 속성이 여전히 앱이 적용한 값인 경우에만 원래 값으로 돌린다. 사용자가 음량 또는 음소거를 바꾼 경우 해당 속성을 유지한다. 앱이 적용한 값과 같은 값으로 다시 조작한 경우는 구별할 수 없다.

음량을 바꾸기 전에 복구 파일을 동기화하고 원자적으로 교체한다. 강제 종료 시 즉시 복원은 보장할 수 없지만 다음 실행/녹음 시작에서 복구를 시도한다. 연결이 끊긴 장치는 복구 기록을 유지한다. 채널 구조가 바뀌었거나 파일을 저장할 수 없으면 임의로 복원/조절하지 않는다.

## 원본 변경 경계

- extensions/audio_ducking: 공통 엔진, 직렬 작업 스레드, 설정 명령, OS별 백엔드.
- pipeline.rs: 마이크 시작 전 begin, 캡처 종료/Idle에서 end.
- commands/ask.rs: Ask 시작/종료/실패/취소 연결.
- lib.rs: 서비스 초기화·종료 및 두 설정 명령 등록.
- GeneralPane.tsx: 별도 AudioDuckingSetting 컴포넌트 연결.
- Cargo.toml/lock: Windows typed Core Audio API 의존성 명시(이미 잠금 파일에 있던 windows0.61 사용).

포크 설정 파일 h-audio-ducking.json, 임시 복구 파일 h-audio-recovery.json은 앱 데이터 디렉터리에 저장한다. 원본 설정 백업/복원에는 이 별도 파일이 포함되지 않는다. 개인 음성·전사·키는 저장하지 않는다.

## 플랫폼

- macOS: Core Audio. 장치 UID로 식별. 출력 master volume 또는 쓰기 가능한 출력 채널들을 사용하며 채널별 비율을 보존. 음소거가 없으면 출력 음량0으로 대체.
- Windows: Core Audio MMDevice/IAudioEndpointVolume. 출력 endpoint ID로 식별. COM은 전용 스레드에서 초기화/해제.
- Linux: pactl JSON 인터페이스. PulseAudio 또는 PipeWire의 PulseAudio 호환 서버와 pactl이 필요. sink 이름/채널 순서를 보존. 명령은 shell 없이 인자 배열로 실행하며 제한 시간을 둠. 순수 PipeWire만 있는 구성은 현재 미지원이며 음량 조절을 건너뜀.

Windows/Linux 실기 검증은 사용자 계획대로 마지막 단계에 수행하며 아직 검증 완료가 아니다. Windows API 호출 시그니처는 가져온 windows0.61 생성 소스와 대조했지만 Windows 빌드/실행은 별도로 검증해야 한다.

## 검증

공통 엔진: 감소/복원, 음소거/취소, 중복 시작, 사용자 변경, 장치 교체, 재시작 복구, 쓰기 실패, 복구 파일 저장 실패, 장치 연결 해제, 음량/음소거 개별 복원 검사.
Mac 실제 장치: opt-in actual_output_reduces_and_restores 테스트에서 reduce/mute와 원래 값 복원을 확인했다.
프런트엔드: 저장 값 로드/즉시 저장, 저장 실패 시 원래 설정 유지. 전체451개 테스트 통과.
전체 Rust 최종 결과와 설치 상태는 HANDOFF.md 참조.

실제 음악·유튜브 재생 중 발화 및 물리적인 헤드폰 교체 검증은 별도로 확인해야 한다. 자동 검사에서 장치 전환은 가짜 백엔드로 검사했다.
