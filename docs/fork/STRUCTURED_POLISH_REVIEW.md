# 구조화 프롬프트 검토 결과

후속: [3차 통합안과 16회 재검사](STRUCTURED_POLISH_V3_REVIEW.md). 아래는 1·2차 후보의 이전 결과다.

2026-09-10. **앱 적용 보류: 구조는 일부 개선됐지만 선택지 누락이 재현됐다.**

대화에서 사용한 개발 요청을 재구성한 텍스트 10개를 기존안/간소화 1차안/보강 2차안으로 비교했다. 실제 녹음 10개가 아니며 STT 비교도 아니다. Gemma4:12b, temperature 0.3, reasoning_effort none; 총 30회 정상 완료. 각 문장/안 1회이므로 반복 안정성/통계적 우열은 확인하지 않았다. 기존안은 일반 문맥의 앱 프롬프트 fixture이고 후보는 독립적인 편집 프롬프트다. 실제 앱 전체 경로 비교가 아니다.

## 판단

- 2차안은 복수 요구에서 결과 보고까지 4개 목록으로 분리했다. 기존안은 결과 보고를 공통 제약 문장에 섞었다.
- 자기 수정은 테스트→통과 시 커밋을 번호로 표시했고 푸시 금지를 보존했다.
- 경로/숫자/포트와 짧은 질문, 불확실성, 쿠버라는 명시적 이름은 보존했다.
- **1차·2차안 모두 선택지 ‘최소’를 누락했다. 기존안은 네 선택지를 유지했다. 교체를 권하지 않는다.**
- 두 요청을 한 문장으로 합치는 경향이 남았다. UI 배치 요청도 목록화하지 않았다. 문장 하나로도 읽힐 수 있으나 강한 구조화 목표에는 미달한다.
- Windows/Linux 실기기 검증 연기의 대상을 ‘실제 기기’로만 표현해 Mac 검증과의 관계가 덜 명확해졌다.
- 2차안은 제시도→재시도, 하모글→항목을 교정했다. 원음 없이 합성한 문맥 시험이며 일반적인 오류 복구 보장이 아니다.
- ‘변경하지 말고’를 ‘변경하지 마’로 쓰는 등 말투 강도가 조금 바뀐다. 추가 검토가 필요하다.

## 제안

구조화 예시의 방향은 검토할 수 있지만 이 후보를 그대로 적용하지 않는다. 특정 오인식 단어를 계속 추가하기보다 기존 의미/선택지 보존 규칙을 유지한 통합 후보 또는 동일 입력의 다른 LLM 비교가 필요하다. 선택지 누락과 플랫폼 범위가 해결된 출력으로 적용 여부를 다시 판단한다. 다른 스타일/번역/사용자 장면에 확대 적용하지 않았다.

Whisper는 현재 CPU 실행이다. local_stt/mlx.rs의 use_mlx는 qwen만 허용하며 빌드 스크립트는 GGML_METAL=OFF다. 다운로드 항목 추가와 MLX 지원은 별도 작업이다.
