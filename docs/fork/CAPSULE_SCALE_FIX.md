# 녹음 종료 시 캡슐 확대 왜곡 수정

2026-09-11. 녹음 종료 후 변환/다듬기 표시가 비정상적으로 확대되는 경로를 브라우저에서 재현했다.

원인은 Capsule의 바깥 motion.div에 지정한 layout 애니메이션이다. 실제 CSS 크기는
360×100에서 232×44로 바뀌지만, Motion이 이전 크기를 재현하려고 첫 프레임에
scaleX=1.551724, scaleY=2.272727을 적용한다. 그 안에 새로 마운트한 상태 문구와 아이콘도
함께 늘어난다. 네이티브 창은 작은 목표 크기로 별도 변경하므로 확대된 내용이 잘릴 수 있다.
스타일 메뉴까지 열려 있으면 높이 차이가 더 크다. 이는 사용자 현상의 재현 가능한 원인 경로이며
장치별 WKWebView나 모니터 배율 문제까지 모두 배제했다는 뜻은 아니다.

바깥 셸은 일반 div로 바꿔 목표 크기를 즉시 적용한다. 상태 내용의 기존 짧은 opacity/blur
전환과 작업 표시기 애니메이션은 유지한다. 입력/프롬프트/네이티브 창 위치 코드는 변경하지 않는다.
Motion의 scale 기반 레이아웃 및 자식 왜곡 설명: https://motion.dev/docs/react-layout-animations

검증:
- 실제 Chrome 렌더링, 실제 Capsule 및 Framer Motion 사용, Tauri 호출만 모의 처리.
- 미리보기/스타일 메뉴 → 변환/다듬기, 녹음 → 출력, 빠른 변환 → 다듬기 → 출력.
- DPR 1/2에서 6개 경로씩 12개 검사, 각 24프레임(총 288프레임) 크기 왜곡 없음.
- 수정 전 소스로 같은 검사를 실행하면 첫 경로에서 배율 1.55/2.27로 실패한다.
- 수정 후 첫 프레임부터 셸 232×44, 문구 높이 15.125px 유지.
- UI 497개 테스트 통과. 기존 UI 검사는 Motion을 모의 처리하므로 이 문제를 검출하지 못했다.
- 브라우저 검사는 실제 녹음, OS 창 크기 변경, WKWebView 실사용 검사를 대신하지 않는다.

재실행: Vite를 127.0.0.1:1432에 실행한 뒤 다음 명령을 사용한다.

```sh
H_PLAYWRIGHT_MODULE=/path/to/playwright node scripts/tests/browser/capsule-layout.cjs
```

Playwright와 Chrome은 별도 테스트 환경에 필요하다. 테스트 페이지는 scripts/tests/browser에 있으며
제품 진입점이나 배포 번들에서 가져오지 않는다.

40d249d에서 만든 beta.3 DMG는 이 수정 전 후보이므로 공개하지 않고 최신 소스로 다시 패키징해야 한다.
