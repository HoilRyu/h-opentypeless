# 동일 프롬프트의 Gemma4 / Qwen3.5 비교

2026-09-10. **이번 작업에는 Gemma4를 유지하는 쪽이 낫다. Qwen으로 교체하지 않았다.**

## 방법과 범위

현재 앱의 일반 문맥/구조화 프롬프트 3,405자와 같은 전사문 12개를 사용했다. 직전 길이 비교의 Gemma4:12b current 결과 36개를 기준으로, Qwen3.5:9b에 각 3회씩 36개를 새로 요청했다. 비교 출력은 총 72개이지만 이번에 새로 호출한 것은 Qwen 36회다.

system/user 메시지, temperature 0.3, reasoning_effort none, max_tokens 4096, 비스트리밍 OpenAI 호환 API 동일. 프롬프트 SHA-256 일치. Qwen 36회 모두 정상 종료/비어 있지 않은 응답, reasoning 필드 길이 0. 실제 음성/STT, UI, 인터넷 검색, 다른 API는 시험하지 않았다. 일반 문맥 fixture라서 실시간 앱 전체 요청을 캡처한 실험은 아니다.

설치된 모델만 사용: Gemma4:12b 11.9B Q4_K_M / Qwen3.5:9b 9.7B Q4_K_M. digest는 결과 JSON에 기록했다. 서로 크기가 다르고, 각 조건 3회 소표본이므로 모델 계열 전체의 우열이나 통계적 유의성을 주장하지 않는다. Gemma를 재실행해 시간 교차 비교하지 않았으므로 속도 우열도 판단하지 않는다.

## 결과

| 항목 | Gemma4 12B | Qwen3.5 9B |
|---|---:|---:|
| 반말 → 존댓말 전환(실패) | 0/33 | 5/33 |
| 네 선택지 이름 보존(성공) | 3/3 | 0/3 |
| 제시도/하모글 두 오류 교정(성공) | 3/3 | 0/3 |
| 경로/숫자/포트 보존(성공) | 3/3 | 3/3 |
| '쿠버' 이름과 '정하지 말자' 제안 말투 함께 보존(성공) | 0/3 | 3/3 |

반말 11문장 × 3회, 존댓말 대조군 1문장 × 3회를 구분했다. 선택지는 단순 문자열 존재가 아니라 메뉴 이름으로 보존됐는지 사람이 평가했다. 마지막 행에서 Gemma도 쿠버 이름은 보존했지만 '말자'를 '하지 마'로 바꿨다. 따라서 한 점수로 모든 품질을 요약하지 않는다.

- Qwen의 존댓말 전환: 기능 질문 3회, 플랫폼 검증 요청 2회.
- 선택지 '최소/깔끔하게/구조화/전문적으로'를 '깔끔하게 구조화된 전문적인 메뉴', '최소한 깔끔하게 구조화되어…'처럼 일반 설명으로 바꿨다.
- '제시도'는 재시도로 교정했지만 '하모글'은 3회 모두 '하모그램'으로 변경했다. 불확실한 인식 오류를 해결하지 못하고 다른 부정확한 표현으로 바꾼 것이다. 이는 원음 없는 합성 오류 사례다.
- multi에서 결과 보고가 목록 밖에 남은 경우 2회, 모든 작업을 나열하면서 공통 제약까지 목록에 넣은 경우 1회였다. Gemma는 3회 모두 4작업과 공통 제약을 분리했다.
- Qwen의 존댓말 대조군 2회에는 '보여줘 주세요'라는 부자연스러운 표현이 나왔다. 나머지 1회는 자연스러운 존댓말이었다.
- Qwen은 '정하지 말자'라는 표현을 3회 모두 유지했다. 이 부분은 Gemma보다 나았다.
- 두 모델 모두 이 표본에서는 질문에 직접 답하거나 구현을 실행하는 응답은 만들지 않았다.

## 결론과 현재 상태

Qwen으로 바꾸는 것만으로 반말 보존 문제를 해결할 근거가 없으며, 선택지 보존과 오류 교정은 더 나빴다. 기존 Gemma4와 구조화 지침을 유지한다. 시험 후 Qwen을 메모리에서 해제하고 Gemma4만 다시 준비한 상태를 확인했다. 앱 설정은 gemma4:12b/structured 그대로다.

Gemma의 0/33은 실사용에서 이미 확인된 말투 전환을 부정하거나 문제가 해결됐음을 뜻하지 않는다. 또한 이 결과만으로 원인이 모델뿐이라고 단정할 수 없다. 현 시점에서 모델 교체나 대폭적인 프롬프트 축소보다, 실제 실패 문장에 대해 높임 수준 유지에만 좁게 초점을 둔 변경을 따로 검토하는 편이 타당하다. 이번에는 새 프롬프트 적용/다운로드/설치/커밋/푸시를 하지 않았다.
