# 구조화 프롬프트: 짧은 역할 분담과 숫자 정정

## 변경

기존 d033d8a의 구조화 프롬프트를 현재 제품 소스에 반영하고, 음성 평가에서 발견한
짧은 역할 분담과 숫자 정정 문제를 추가로 보완했다.

- 서로 다른 담당자에게 배정한 업무는 문장 길이와 무관하게 담당자별 글머리표로 분리한다.
- 화자 자신의 역할도 같은 목록에 포함한다. 나는/저는 같은 지칭과 반말/존댓말을 보존한다.
- 목록을 나눌 때 남는 연결 어미는 같은 말투의 종결 어미로 완성한다.
- 공통 승인 조건과 전송 금지는 역할 목록 뒤에 별도로 둔다.
- 아직 고려 중인 역할과 제안은 확정 배정으로 바꾸지 않고 그 불확실성을 보존한다.
- 아라비아 숫자, 한글 수사, 혼합 표기, 금액/소수점/시간/긴 요청의 수량 정정은 마지막 값으로 정리한다.
- 서로 다른 대상의 수량, 과거/현재 비교, 조건부 대안은 둘 다 보존한다.
- 제목이나 문구 자체를 보존하라는 경우에는 그 안의 숫자와 ‘아니’도 그대로 둔다.

위 규칙은 LLM 편집 지침과 별도 주제의 예시로 구현했다. 임의의 숫자 문자열을
정규식으로 삭제하는 후처리는 추가하지 않았다.

Ollama의 structured 받아쓰기에서는 장면 덮어쓰기/번역/선택 텍스트 편집이 없을 때
요청 temperature=0을 사용한다. 실제 HTTP 요청의 temperature와 reasoning_effort=none을
검사한다. 다른 제공자와 다른 작업은 기존 설정을 유지하고 기존 GLM 예외도 유지한다.

## 확인한 출력

입력: 자료 조사는 민지가 맡고 검토는 준호가 맡아. 나는 최종 승인을 할게. 승인 전에는 외부에 보내지 마.

```text
- 자료 조사는 민지가 맡아.
- 검토는 준호가 맡아.
- 나는 최종 승인을 할게.

승인 전에는 외부에 보내지 마.
```

입력: 파일은 3개, 아니 4개야. 전부 옮기지 말고 마지막 파일만 복사해줘.

```text
파일은 4개야. 전부 옮기지 말고 마지막 파일만 복사해줘.
```

## 평가 구성

- 개발/회귀 20개: 짧은 역할 분담, 숫자 정정, 비교/대안/인용/말투 경계 사례.
- 앞선 음성 평가의 STT 결과 및 정답 전사 40개.
- 기존 구조화 회귀 30개.
- 새 보류 평가 6개를 2회씩, 원래 역할/정정 4개를 추가로 2회씩 검사.
- 기본 구성 110개이며, 희망형 예시 적용 대상 4개는 추가 반복해 최종 검토 결과는 114건이다. 이번 실행은 이미 얻은 STT 텍스트를 재사용하는 **LLM 평가**이며,
  새 마이크 녹음이나 실제 채팅창 붙여넣기 검사는 아니다.

실제 Rust 프롬프트 빌더가 내보낸 structured-false 값과 평가용 프롬프트가 일치한다.
최소/깔끔하게/전문적으로 스타일의 번역 및 비번역 프롬프트 6개는 설치 전 값과 동일하다.
평가 환경은 Ollama gemma4:12b, temperature=0, reasoning_effort=none이다.
다른 모델에서도 모든 경우에 같은 결과가 나온다는 보장은 아니다.

반복 검사 및 새 사례에 사용한 입력은 role-correction-final-suite.json에 보존한다.
개발 과정에서 본 사례는 신규 보류 평가로 재사용하지 않는다. 이전 버전의 중단된
검사는 최종 110회 집계에 포함하지 않는다. 자동 검토 표시는 의미 오류와 구분한다.


## 관련 예시의 조건부 선택

모든 입력에 희망형 요청 예시를 추가하면 일부 짧은 역할 목록의 말투가 흔들렸다.
역할·숫자 정정에 검증된 기본 예시를 유지하고, 구조화 받아쓰기 원문에 `좋겠`이
포함될 때만 희망형 요청 보존 예시를 추가한다. 이 선택은 원고의 내용을 수정하지 않으며
추가 API 호출이나 두 번째 LLM 처리도 하지 않는다. 번역과 선택 텍스트 편집은 제외한다.
다른 표현의 누락을 모두 탐지하는 의미 검사기는 아니다.

## 최종 검증

- Rust 655개 통과, 명시적 로컬 장치/자료 내보내기 검사 8개 생략.
- 실제 HTTP 요청에서 temperature=0, reasoning_effort=none 및 원고에 맞는 예시 포함을 검사했다.
- Rust가 내보낸 기본/희망형 프롬프트 두 가지가 평가 프롬프트와 정확히 일치한다.
- 기본 프롬프트가 바뀌지 않는 106개 결과는 전체 요청 JSON SHA256이 같음을 확인해 재사용했다.
- 희망형 예시가 적용되는 4개 요청은 2회씩 새로 평가했다. 총 114개 결과를 기록했다.
- 동일 요청의 반복 출력 차이는 없었고, 역할 분담 및 숫자 정정 사례는 검토를 통과했다.
- 자동 검사 표시 2건은 기존 메뉴/모드 이름 요청이 글머리표 대신 평문으로 나온 경우다.
  이름과 저장 조건은 보존됐다. 이를 의미 오류나 이번 역할 분담 실패로 집계하지 않았다.
- 이전 STT가 손상한 '백업 파일은 그대로고'의 어미와, 금지 조건이 번호 목록에 남는
  기존 형식 사례는 이번 두 문제와 별도로 기록했다. 모든 음성 인식 오류를 해결했다는 뜻은 아니다.

결과: evaluation/voice/results/2026-09-11-role-corrections.
재실행 시 해당 디렉터리의 prompts.json과 role-correction-final-suite.json을 사용한다.
예시 선택 기준이 다르면 평가 prompt_key도 함께 변경해야 한다.
