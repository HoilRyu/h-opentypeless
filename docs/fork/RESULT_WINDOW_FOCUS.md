# 입력 대상 판정과 결과 창 — 2026-09-09

## 조사 결과

사용자가 커서를 옮기지 않았는데 복사 창이 표시됐다고 보고했다. 최근 기록 194, 196, 197의 출력 오류는 `TargetChanged`였다. 이전 버전에는 당시 기대 PID/현재 PID 기록이 없어 각 사건의 정확한 원인은 확정하지 못했다.

코드에서는 녹음 시작 대상을 백그라운드 캐시에서 가져오고, 출력 전 검사는 AppleScript를 포함한 전체 컨텍스트 수집을 사용했다. 따라서 직전에 앱을 전환한 경우의 오래된 캐시와 컨텍스트 조회 실패가 잘못된 대상 변경 판정을 만들 수 있었다. 이 판정은 마우스 좌표 자체를 비교하는 기능이 아니다.

## 변경

- 녹음 시작 시 실제 활성 앱의 식별자를 읽는다. macOS에서는 NSWorkspace의 frontmostApplication/PID/bundle ID만 사용한다.
- 출력 직전과 스트리밍 중에도 macOS 활성 앱을 직접 확인한다. 조회 불가 시 15ms 뒤 한 번 재시도하되 실제 다른 앱이 확인된 경우에는 그대로 차단한다.
- 시작 대상을 확인하지 못한 경우도 자동 입력을 허용하지 않는다.
- 진단은 `h-focus-events.log`에 시각, 판정, PID, 식별자 일치 여부만 남긴다. 텍스트, URL, 창 제목, 키는 기록하지 않는다. 128KiB 파일 두 개로 제한한다.
- 결과 창은 캡슐 위 10 논리 픽셀 간격에 배치하고, 위쪽 공간이 부족하면 아래로 배치한다. 캡슐이 있는 모니터의 작업 영역과 배율을 적용한다.
- 결과 창에 캡슐의 그라데이션, 민트 테두리, 둥근 모서리와 버튼 스타일을 적용했다. 제목과 안내를 다른 줄에 두는 기존 잘림 방지 수정도 유지한다.
- 키체인 helper 바이너리/승인 방식은 변경하지 않았다.

## 검증

- app_detector 테스트 29개, 배치 테스트 2개, AskPanel 테스트 20개 통과.
- 오래된 컨텍스트와 실제 활성 앱이 다를 때 실제 앱으로 시작하는 경우, 실제 앱 전환, 시작 대상 조회 불가를 검사했다.
- 화면 위/아래, 음수 좌표 모니터, 배율과 화면 경계 계산을 검사했다.
- macOS 빌드/자체 서명 strict 검증 후 `/Applications/H-OpenTypeless.app` 교체 및 실행 완료.
- 사용자에게 동일 입력칸 유지와 다른 앱 전환 두 경우의 실제 음성 입력/배치 확인을 요청했다. 아직 결과 대기. Windows/Linux 실기기 검증은 수행하지 않았다.

앱 내부에서 입력칸만 바뀌는 상황을 완전히 식별하는 기능으로 확대 해석하지 않는다. 기존의 안전한 복사 fallback과 메인 창을 함께 띄우지 않는 동작은 유지한다.

## 비활성 창 첫 클릭 — 후속 수정

사용자가 닫기 버튼을 두 번 눌러야 한다고 보고했다. 메인 창 동반 표시를 막기 위해 macOS에서 결과 창을 활성화하지 않고 표시하지만, WebView의 `acceptFirstMouse`는 기본값 false였다. 이 조합에서는 첫 클릭이 창 활성화에만 소비된다. ask 창 설정과 설정 미존재 시 생성하는 fallback builder 모두 첫 클릭 수신을 켰다. 닫기/복사 버튼에 동일하게 적용되며 결과 창을 표시할 때 앱 전체를 활성화하는 호출은 추가하지 않았다. 빌드 검증과 실제 클릭 결과는 아래 인계 기록을 참조한다.

## 닫은 뒤 메인 창으로 포커스가 넘어가는 문제

첫 클릭 수신은 클릭 시 앱 활성화를 막지 않는다. 일반 NSWindow를 클릭하면 H 앱이 활성화되고, 해당 창을 숨긴 뒤에는 열린 H 메인 창이 포커스를 받을 수 있다.

macOS ask 창을 `tauri-nspanel`의 NSPanel로 한 번 전환해 재사용한다. `NonactivatingPanel` 스타일, key/main 창 불가, 다른 앱 활성화 시에도 표시 유지로 설정한다. 표시/변환은 메인 스레드에서 수행한다. 닫기는 기존 hide 경로를 사용한다. 이전 앱을 강제로 다시 활성화하는 타이머나 포커스 복원 코드는 추가하지 않는다. 복사/닫기 버튼을 마우스로 사용하는 결과 카드이며, 이 패널은 키보드 포커스를 가져가지 않는다.

의존성은 macOS 전용이며 검토한 커밋 `c9ec2130422200f0863b23dfdad02b133a529b07`로 고정했다. plugin은 네이티브 window class를 변환하므로 Tauri/tao/plugin 업그레이드 시 표시·닫기·재표시·드래그·전체화면 검증이 필요하다. Windows/Linux 경로는 일반 Tauri 창을 유지한다.
