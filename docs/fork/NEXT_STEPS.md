# 다음 작업

## 현재 기준

2026-09-08 사용자 확인: 자체 서명 버전 B 설치 후 음성 인식이 정상 동작한다. A/B 바이너리 차이, 동일 서명 식별 조건, 업데이트 후 접근성 권한 유지와 사용자 음성 입력 확인까지 완료했다. 다른 Mac의 다운로드 설치 검증과 Windows/Linux 실제 검증은 아직 수행하지 않았다.

## 권장 진행 순서

1. Mac 남은 동작 확인: LLM 처리 중 다른 창으로 이동할 때 결과 복사창이 유지되는지 재검증한다. 사용자의 최신 정상 음성 입력 확인을 이 특정 상황의 검증으로 확대하지 않는다. 녹음 취소·엔진 연결 실패 후 복구, 수동 음량 변경/장치 변경의 복원도 확인한다.
2. Mac 배포 산출물 준비: 현재 debug 빌드와 구분해 release 빌드·자체 서명·ZIP/DMG·SHA256 체크섬 생성 과정을 구성한다. 개인키 암호화 백업은 사용자가 보관할 위치/암호를 선택한 후 진행한다. GitHub에서 다운로드한 앱의 설치·최초 실행 안내를 별도 Mac에서 검증한다. Apple 공증은 없음을 명시한다. 릴리스 업로드/발행은 사용자가 요청할 때 진행한다.
3. Android 연결 구현: 기존 mobile-opentypeless는 참고만 하며 필요한 Android 코드를 H 저장소로 선별 이관한다. H 앱 안에 모바일 연결 모듈을 넣어 별도 Python 게이트웨이 없이 앱을 켜면 동작하도록 한다. STT/LLM 및 사용자 프롬프트 경로는 데스크톱의 기존 구현을 재사용한다. 모바일 연결은 설정에서 켜며 사용자가 선택한 내부 인터페이스/WireGuard 환경을 따른다. 기존 연결키 없는 방침을 유지한다.
4. 플랫폼 배포 설정 정리: 포크 전용 CI/릴리스 경로를 정리하고 upstream의 Apple 유료 서명 secret 필수 조건 및 원본 릴리스 설정을 그대로 사용하지 않도록 한다. 공식 릴리스 업데이트 통합 문서를 현재 변경 경계와 맞춘다.
5. Windows/Linux 실제 검증: 사용자 결정대로 마지막에 진행한다. 각 OS 빌드·설치·트레이·단축키·자동 입력·음량 복원·Android 통신을 확인한다. Linux는 X11/Wayland와 오디오 환경을 구분하고 미검증 플랫폼을 검증 완료로 배포하지 않는다.

최초 입력 앱/커서 자동 복원 실험은 재도입하지 않는다. 현재 정책은 대상 앱 변경 시 복사창이다. 이번 정리는 계획이며 새로운 구현 작업이나 릴리스 발행을 시작한 것은 아니다.
