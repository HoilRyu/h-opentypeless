# H 첫 실행 튜토리얼 계획

2026-09-10. 내장 STT 기능 커밋: `8b46610`. 이번 문서는 튜토리얼 계획이다. 선행 MLX 통합은 별도로 진행했고 [검증 기록](MLX_STT_VERIFICATION.md)을 참고한다. 튜토리얼은 0.1.45-beta.1에서 처음 구현한 뒤 0.1.45-beta.2에서 간소화했다. 현재 결과와 검증 범위는 [TUTORIAL.md](TUTORIAL.md)를 참고한다.

## 선행 작업 상태: 내장 MLX 구현 완료

MLX 통합과 자동 검증·설치가 완료됐다. 구현 결과와 한계는 [MLX_STT_VERIFICATION.md](MLX_STT_VERIFICATION.md)에 기록했다. 아래는 구현의 기준이 된 계획이다. 아래 MLX 항목과 지연 측정은 선행 작업을 결정했던 배경이며 미구현 작업 목록이 아니다.

사용자는 기존 MLX GPU 방식의 성능을 유지하면서 앱만 실행하는 경험을 원한다. CPU 전환에 따른 성능 차이를 사전에 충분히 설명하지 못했다. 이 요구에 따라 튜토리얼보다 Apple Silicon용 MLX 통합을 먼저 진행했다.

- 기존 Local / Custom Whisper 연결 UI는 남아 있다. 외부 MLX 서버 자체는 제거했으므로 종전 방식 복귀에는 실행 환경 복구가 필요하다.
- Qwen 내장 엔진 설정: 자동(기본), MLX GPU, CPU. 자동은 OS/CPU 아키텍처, Metal 및 실제 MLX 로드 가능 여부, 엔진 버전을 확인한다. 단순 arm64 판정만으로 MLX 지원이라고 표시하지 않는다.
- 호환되는 Apple Silicon Mac에서는 MLX를 우선 사용한다. 미지원 OS는 해당 OS에서 검증한 엔진만 제공하며 Windows Qwen의 현재 미지원 상태를 유지한다.
- 첫 macOS arm64 배포에는 Python/MLX 종속성을 앱이 관리하는 서명된 실행 환경으로 포함한다. 별도 엔진 팩은 후속 과제로 둔다. 사용자의 pip 설치나 외부 서버 수동 시작을 요구하지 않는다. 앱 전용 워커/통신 경로로 실행·종료를 관리한다.
- 현재 Qwen 가중치는 공식 원본이므로 재사용을 우선하고 tokenizer 설정 등 부족한 보조 파일만 검증하여 추가한다. 파일 호환성은 실제 MLX 실행으로 확인한다.
- 단일 워커/모델, 제한된 유휴 보관, 메모리 회수, 취소·앱 종료 정리를 함께 검증한다. 무제한 모델 상주는 도입하지 않는다.
- 현재 사용 중인 실행 엔진을 화면에 표시한다. MLX 실패 시 CPU로 조용히 전환하지 않고 이유와 성능 차이를 알리고 재시도/CPU 사용을 선택할 수 있게 한다.
- 동일 음성·1.7B 가중치로 GPU/CPU와 최초/반복 실행을 비교한 뒤 기본값을 확정한다. 모델 크기를 몰래 변경하지 않는다.

참고: https://github.com/moona3k/mlx-qwen3-asr (Apple Silicon/Metal, Python API와 Session API, 원본 가중치 지원).

## 이전 CPU 구현의 지연 진단 기록

사용자가 내장 Qwen3-ASR 1.7B 전환 후 체감 지연을 보고했다. 당시 기존 외부 MLX 서버는 Apple Silicon GPU 경로였으나 내장 qwen-asr는 CPU/BLAS 경로였다. 모델 이름이 같아도 같은 실행 성능을 보장하지 않는다. 당시 구현은 매 녹음 종료 후 약 4.7 GB의 파일을 SHA-256 검증하고 새 프로세스에서 모델을 로드한다. 자원 회수에는 유리하지만 반복 사용 시 지연 비용이 있다.

MLX 통합 전 이 Mac의 2.97초 한국어 합성 음성 독립 측정:

| 구간 | 측정 |
|---|---:|
| Python hashlib로 전체 파일 SHA-256 검증 | 2.14초 |
| 설치된 네이티브 엔진의 시작·로드·전사·종료 | 1.91초 |

한 번의 측정이며 OS 파일 캐시, 시스템 부하 등에 영향을 받는다. Rust 앱 내부 계측이 아니고, LLM·키체인·텍스트 입력 시간은 포함하지 않는다. 따라서 사용자가 경험한 전체 지연의 원인을 이 수치만으로 확정하지 않는다.

### 지연 진단 시 검토했던 항목

아래는 진단 배경이다. 실제 구현 순서는 별도 MLX 계획의 A~E 단계를 따른다.

1. 실제 앱 경로에 구간별 시간 계측: 녹음 종료 → 무결성 검증 → 엔진 시작/전사 완료 → LLM 완료 → 입력 완료. 음성/전사문/키는 기록하지 않고 시간·모델 ID·성공 여부만 기록한다. 동일한 짧은/긴 음성으로 첫 실행과 반복 실행을 구분한다.
2. 반복 검증 비용 감소: 최초 다운로드 검증 유지. 앱 세션 내 확인한 파일의 식별자·크기·수정 시각을 확인해 검증 결과를 재사용하는 방식을 검토한다. 설치/교체/삭제/파일 변경 시 무효화하며, 별도 검증 기능과 변조 테스트를 둔다. 취소와 다운로드 중 파일의 실행 금지 조건은 유지한다.
3. 측정 후 필요한 경우 모델 유지 옵션 검토: 단일 워커, 한 작업, 유휴 시간 만료, 메모리 부족 시 해제, 종료·취소·장애 시 회수. 기존 CLI는 일회성 실행이므로 재사용 프로토콜 구현/검증이 필요하다. 무제한 상주나 작업별 워커 누적은 허용하지 않는다.
4. Apple Silicon GPU 경로는 별도 엔진 확장으로 검토한다. 현재 C 엔진에 옵션 하나를 켜는 작업으로 간주하지 않는다. 배포 용량·라이선스·종속성·macOS 요구 사항과 Windows/Linux CPU 대체 경로를 함께 평가한다.

사용 중인 Qwen 1.7B를 임의로 다른 모델로 변경하지 않는다. 튜토리얼 제작 전 최소한 실제 지연 구간과 개선 우선순위를 확정한다.

## 튜토리얼 목표와 화면 흐름

사용자가 서버 구조를 이해하지 않아도 첫 음성 입력에 성공하도록 한다. 기존 사용자의 설정·모델·지침을 보존한다. H에는 계정/업그레이드/관리형 클라우드 가입 단계를 표시하지 않는다.

1. **음성 인식 준비**
   - 내장 STT / 기존 외부 제공자 선택. 설치된 모델은 재사용한다.
   - 메모리·지원 OS·다운로드 크기·속도/정확도 선택 기준 안내. 성능 보장 표현은 피한다.
   - 다운로드, 일시 정지, 이어받기, 실패 복구를 기존 모델 관리자와 공유한다.
   - 내장 모델은 엔진 지원 + 파일 준비 + 선택 완료를 확인한다. 외부 제공자는 실제 연결 테스트를 사용한다.
2. **AI 다듬기 선택**
   - 선택 기능임을 명시하고 ‘나중에 설정’ 제공. 건너뛰어도 STT만으로 사용 가능하다.
   - Ollama/API 선택과 연결 시험. 기존 모델·키·사용자 지침은 유지한다.
3. **권한과 단축키**
   - Mac: 마이크·손쉬운 사용, Windows: 마이크 상태, Linux: 오디오/Wayland 입력 제약에 맞춰 안내한다.
   - 실제 저장된 단축키와 누르고 말하기/토글 방식을 보여 준다. 고정 예시 키로 안내하지 않는다.
   - 권한 거부 후 재검사와 설정 화면으로 이동을 지원한다.
4. **실제 음성 입력 연습**
   - 앱 안의 전용 시험 입력칸에서 짧은 문장을 녹음하고 실제 결과를 확인한다.
   - 전사 원문과 선택적 다듬기 결과, 단계별 대기 시간을 구분한다.
   - 현재 QuickTestStep은 애니메이션 데모이므로 성공 검증으로 재사용하지 않는다.
   - 다른 앱에 테스트 문장을 자동 입력하거나 전송하지 않는다. 포커스를 잃으면 복사 창으로 이어지는 동작도 안내한다.
5. **완료와 일상 사용**
   - 설정 저장 성공 후 완료 처리. 실패 시 오류를 표시하고 재시도한다.
   - 메뉴 막대/트레이, 녹음 취소, 복사 창 단축키를 짧게 안내한다.
   - 모바일 연결은 선택적인 후속 안내로 연결한다.

## 구조

- H 전용 흐름 컴포넌트를 추가하고 기존 Onboarding 진입점에 작은 분기를 둔다. 원본 계정/클라우드 흐름의 숫자 인덱스를 계속 우회하는 방식은 확장하지 않는다.
- 모델 관리자와 제공자/연결 시험 UI는 설정 화면과 공유해 중복 구현을 줄인다.
- 단계 ID 기반의 상태와 진행 표시를 사용한다. 다운로드·권한·연결 상태를 단계 완료 조건과 분리한다.
- 첫 실행 자동 진입, 중단 후 재개, 설정에서 ‘사용 방법 다시 보기’를 제공한다. 업데이트만으로 기존 사용자에게 강제 재실행하지 않는다.
- 다시 보기에서는 현재 설정을 기본값으로 사용하고 실제 변경을 저장할 때만 적용한다. 건너뛰기는 설정 초기화가 아니다.
- 기존 코드의 저장 실패 무시 후 완료 처리는 H 흐름에서 사용하지 않는다.

## 작업 단위와 완료 기준

1. MLX 계획의 환경 감지·통합·실제 지연/안정성 검증을 먼저 마친다.
2. H 튜토리얼 상태·단계·재진입 기반 구현.
3. STT/선택적 LLM/권한 설정 연결.
4. 실제 녹음 연습과 단계별 상태·완료 안내.
5. 저장 실패, 네트워크 단절, 디스크 부족, 다운로드 취소·재개, 미지원 엔진, 권한 거부, 재실행 회귀 검증.

모델/LLM 준비 상태에 맞는 경로로 첫 입력이 가능하고, 중단 후 이어갈 수 있으며 기존 설정이 보존되어야 한다. Mac 실제 검증을 우선하고 Windows/Linux 구조 및 조건부 UI는 함께 구현하되 실기기 검증 완료 전 검증 완료로 표시하지 않는다.
