# 모바일 연결 독립 메뉴 계획

상태: 메뉴 분리 및 화면 구성 구현 완료 (2026-09-09). macOS 설치·화면 확인 완료.

## 목적과 배치

H에서 추가한 모바일 게이트웨이를 일반 설정에서 분리해 쉽게 찾도록 한다.
사이드바 순서: 홈 → 모바일 연결 → 설정 → 기록. 스마트폰 아이콘과 ‘모바일 연결’ 이름을 사용한다. 현재 지원 플랫폼은 화면 안내에서 Android라고 명확히 표시하며 iOS 지원을 암시하지 않는다.

## 1. 기존 기능을 그대로 이동

- `src/components/MobileConnection/index.tsx`에 페이지를 만들고 `mobile` 라우트를 추가한다.
- `ForkSettings/MobileConnectionSetting.tsx`를 재사용한다. GeneralPane의 기존 항목은 제거해 중복 설정을 방지한다.
- `get_mobile_status`와 `set_mobile_config` 및 저장된 enabled/address/port를 유지한다. 페이지 진입·이탈 때문에 서버를 켜거나 끄지 않는다.
- macOS, Windows, Linux 공통 React 화면으로 구현한다. 데스크톱 앱이 모바일 게이트웨이를 관리하는 현재 구조를 유지한다.

## 2. 화면 구성 정리

1. 제목·설명: Android 음성 키보드를 이 컴퓨터의 STT·AI 다듬기에 연결한다.
2. 상태: 꺼짐 / 연결 대기 / 오류. 서버가 대기 중인 것을 ‘휴대폰 연결됨’으로 표시하지 않는다. 현재 API에는 연결된 기기 목록·세션 정보가 없다.
3. 기본 영역: 연결 켜기·끄기, 실제 연결 주소, 주소 복사, 상태 새로고침.
4. 접힌 고급 설정: 수신 IP, 포트, 저장·적용. 네트워크 주소 후보와 잘못된 값·바인딩 오류를 표시한다.
5. 짧은 연결 안내: Android 앱 설정에 주소 입력 → 같은 내부 네트워크 또는 WireGuard 사용 → 데스크톱 H 앱 실행 유지. 기존의 연결 키 없는 접근 범위를 명확히 안내한다.
6. 사용 모델: 모바일에서 실제 지원하는 STT 경로와 데스크톱 AI 설정의 관계를 설명하고 해당 설정으로 이동하는 링크를 제공한다. 지원하지 않는 STT 설정이면 조치 방법을 표시한다.

첫 단계에는 QR 페어링, 자동 검색, 기기 관리, 새 인증 체계를 추가하지 않는다. 현재 Android 앱에 없는 프로토콜이나 스캐너를 화면에서 지원한다고 표현하지 않는다.

## 3. 검증과 완료 조건

- 메뉴 클릭과 직접 라우트 접근이 같은 화면을 표시하며 일반 설정에는 중복 카드가 없다.
- 저장된 주소와 포트가 유지되고, 잘못된 포트·사용 중 포트·127.0.0.1 안내를 확인한다.
- 페이지 전환·창 닫기만으로 실행 중 게이트웨이가 중단되지 않는다.
- 모바일 음성 요청·취소·응답과 데스크톱 음성 입력이 기존대로 동작한다.
- 밝은/어두운 테마, 작은 창, 키보드 탐색, 한국어·영어를 확인한다.
- macOS 및 Android 실제 연결을 우선 검증하고 Windows·Linux 실제 검증은 사용자 일정에 따라 마지막에 수행한다.

## 현재 수행한 별도 변경

계정·업그레이드 진입점은 H 기능 플래그로 비활성화했다. 원본 페이지·인증 코드는 upstream 병합을 위해 보존한다. 라이선스 및 저작권 고지는 유지한다. 모바일 메뉴 분리는 후속 작업에서 구현했다.

## 구현 검증

- 모바일 상태·복사·포트 검증, 탐색 및 번역 키 검사: 8개 통과.
- macOS 빌드 및 기존 자체 서명 검증 통과, /Applications 앱 교체.
- 실제 앱의 모바일 메뉴 진입, 상태 새로고침, 일반 설정에서 중복 제거 확인.
- 페이지 이동 후 기존 주소 192.168.0.123:8787의 health 응답 정상.
- 이번 화면 변경에서 새 음성 녹음·Android 음성 입력, Windows/Linux 런타임, 밝은 테마와 작은 창의 추가 실사용 검증은 수행하지 않았다.
