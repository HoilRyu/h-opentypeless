# H-OpenTypeless Android 키보드

H 데스크톱 앱의 모바일 연결에 사용하는 독립 Android IME다. 기존 mobile-opentypeless 저장소나 Python 서버를 런타임/빌드에서 참조하지 않는다.

1. H 데스크톱 앱에서 음성 인식과 필요한 AI 다듬기를 설정한 뒤 **모바일 연결** 메뉴에서 연결을 켠다.
2. 이 앱에 H가 표시한 내부 주소를 저장하고 연결 확인을 누른다.
3. 마이크 권한을 허용하고 시스템에서 H-OpenTypeless 음성 키보드를 활성화/선택한다.
4. 시험 입력칸에서 녹음 후 결과를 확인하고 삽입한다.

연결키는 없다. 내부 Wi-Fi/WireGuard를 사용한다. 전체 API/지원 제공자는 `../docs/fork/MOBILE_API.md`를 참고한다.

## 로컬 모드 및 디자인 (0.3.0)

홈 상단의 처리 방식 버튼에서 **이 기기에서 처리 / 내 컴퓨터에서 처리**를 직접 선택한다. 로컬 홈에는 기기와 모델 정보만, 원격 홈에는 컴퓨터 연결 정보만 표시한다. 로컬 모델은 홈의 **모델 관리**에서 음성 인식·문장 교정·교정 지침 탭으로 관리한다. 로컬은 Android 기본 온디바이스 STT / Whisper와 Gemma 4 E2B/E4B Mobile을 지원한다. 모델은 앱에서 별도로 설치하며 기기·모델 준비 상태에 따라 선택 가능 여부를 표시한다. H의 기존 PCM 녹음과 원격 API 규약은 유지한다.

화면은 데스크톱의 차콜 배경·민트 강조색·둥근 카드 스타일을 공유한다. 키보드는 인식 원문과 교정문을 함께 표시하며, 사용할 문장을 선택한 후 삽입 버튼으로 입력한다. 긴 결과는 스크롤하고 녹음·삽입·취소 버튼은 고정한다. Android 기본 STT는 종료 버튼까지 연속 인식한다. 원격/Whisper 녹음의 기존 119초 제한은 유지한다.

사용법, 지원 조건과 검증 범위는 [로컬 모드 문서](LOCAL_MODE.md)를 참고한다.

## 빌드

JDK17 또는21, Android SDK Platform36/Build Tools35.0.0, NDK28.2.13676358, CMake3.22.1이 필요하다. `JAVA_HOME`과 `ANDROID_HOME`을 설치 위치로 지정한 후 실행한다.

```sh
./build.sh assembleDebug testDebugUnitTest lintDebug
```

Gradle wrapper8.13의 체크섬을 고정했다. Gradle 캐시는 ~/.local/share/h-opentypeless/android-tools, 빌드 결과는 ~/.local/share/h-opentypeless/android-build에 저장한다. APK는 app/outputs/apk/debug/app-debug.apk이다. debug 서명 APK는 개인 검증용이며 정식 Android 배포 서명은 별도 작업이다. Mac 자체 서명 인증서를 Android 서명에 사용하지 않는다.

이 Mac에서 기존에 설치된 JDK/SDK 도구를 환경 변수로 가리킬 수 있다. 해당 도구 설치 위치는 소스 코드 의존성이 아니며 다른 컴퓨터에서는 그 컴퓨터의 표준 JDK/SDK를 지정한다.

## 음량 표시 개선 (0.3.1)

기본 STT의 음량 콜백에 묶였던 그래프를 화면 프레임 갱신과 분리했다. 측정값 사이를 보간하고, 300ms 이상 새 값이 없으면 완만하게 줄인다. 임의의 음량을 생성하지 않으며 타이머는 독립적으로 갱신한다. 녹음 종료 또는 키보드가 보이지 않을 때 지속 그리기를 중단한다. 원격/Whisper도 같은 표시 로직을 사용하며 녹음·인식 엔진은 변경하지 않았다.

34개 단위 테스트(음량 보간·오래된 값 감쇠·프레임 주기 독립성·초기화 포함)와 S26 Ultra UI 회귀 검사를 통과했다. 실제 발화 중의 프레임 지연과 기본 STT 콜백 간격은 아직 측정하지 않았으므로, 사용자 환경의 모든 끊김이 해결됐다고 단정하지 않는다.

## 기본 STT 문장 구간 및 음량 이력 (0.3.2)

Android 13 이상에서는 EXTRA_SEGMENTED_SESSION과 1200ms 문장 구간 무음을 요청한다. onSegmentResults는 원문을 누적하고 인식기를 유지한다. 세션 종료 콜백만 기존 수동 종료/재시작 정책으로 처리한다. 종료 대기 시간 초과 시 마지막 부분 원문 보존도 유지한다. 시스템이 요청을 무시하면 기존 onResults 재시작이 남으므로 알림음 제거를 보장하지 않는다. 시스템 음량이나 알림 설정은 변경하지 않는다.

그래프는 같은 음량을 모든 막대에 복제하던 방식에서 최근 약 1초의 음량 이력을 표시하는 방식으로 변경했다. 기본 STT에서는 여전히 서비스가 제공하는 RMS에 의존하므로 실제 PCM 파형이나 주파수 분석 그래프는 아니다. 콜백이 드물거나 일정한 값을 주면 음성과 시각 표시가 정확히 일치하지 않을 수 있다.

도움말의 기본 STT 진단에는 마지막 세션의 인식기 시작·연속 구간·음량 콜백 횟수를 보관한다. 발화 내용과 음성 파일은 이 진단에 저장하지 않는다.

36개 단위 테스트와 S26 Ultra UI 회귀 검사 통과. 한국어 설치 및 새 Intent 지원 조회 응답 정상. 이 응답은 연속 구간 기능의 실제 동작을 보장하지 않는다. 실제 발화 사이 휴지 후 알림음 여부와 시작/구간 횟수 확인이 남아 있다.

## 기본 STT 마이크 스트림 (0.3.3)

S26 Ultra 진단에서 0.3.2가 시작 8회·연속 구간 8개로 구간마다 세션을 다시 시작한 것을 확인했다. Android 13 이상 기본 STT를 앱 소유 AudioRecord → PCM16/16kHz/mono 파이프 → EXTRA_AUDIO_SOURCE 기반 segmented session으로 변경했다. 무음으로 스트림을 닫지 않고 종료 버튼에서만 EOF를 전달한다. 예상치 못한 세션 종료는 원문을 보존하고 오류를 표시하며 반복 재시작하지 않는다. 시스템 알림 음량은 변경하지 않는다.

음량은 같은 마이크의 PCM에서 계산한다. 파이프는 비차단 쓰기와 제한된 버퍼를 사용하며 서비스가 읽지 않으면 오류로 종료한다. 녹음 종료·취소 시 작업 스레드가 마이크를 해제할 때까지 RecordingLease를 유지한다. 음성을 디스크에 저장하지 않는다. Android 12의 기존 시스템 마이크 경로는 유지한다.

기기 검사 결과는 ~/.local/share/h-opentypeless/verification/mobile-redesign/stream-device.log 및 stream-speech-device.log에 기록한다. 스트림 검사는 합성 음성/무음을 주입하며 사용자의 실제 마이크 녹음을 사용하지 않는다. 실제 스피커 알림음의 무음 여부를 측정한 검사는 아니다.

0.3.3 검증: 단위 테스트 38개, 녹음 lease 및 UI 회귀 검사 통과. S26 Ultra에서 12초 무음 스트림이 EOF까지 유지됐으며, 합성 한국어 음성 → 5초 무음 → 동일 음성의 총 17.14초 스트림은 재시작 없이 3개 구간을 반환하고 EOF 후 정상 종료했다. 인식 결과에 앞뒤 테스트 문장의 표식이 모두 있는 것을 확인했다. 서비스가 구간을 나누는 개수는 문장 수와 일치하지 않을 수 있다.

## 버튼 간격과 화면 배치 (0.3.4)

앱 버튼의 세로 간격 12dp, 카드 간격 24dp, 카드 안쪽 여백 20dp를 적용했다. 하단 탐색과 모델 탭에 8dp 가로 간격을 추가하고, 선택된 메뉴는 어두운 민트 배경으로 표시해 실행 버튼과 구분한다. 설명 문장은 작은 회색 글씨로 계층을 나눈다.

키보드는 바깥 여백 16dp, 주요 버튼 높이 56dp, 주요 버튼 사이 12dp, 도구 버튼 사이 8dp를 사용한다. 도구 버튼은 최소 48dp이며 원문 선택은 결과 영역으로 옮겼다. 원문·교정문 카드를 눌러 선택할 수도 있다. 주요 동작과 편집 도구 사이에 12dp 여백을 확보한다. 기존 음성 처리·스트림·수동 종료 동작은 유지한다.

Android Studio의 H_OpenTypeless_UI_API_36 가상 기기(API 36, ARM64, 1080×2400, 420dpi)에서 화면을 렌더링하고 320dp 너비에서 키보드 도구의 크기·간격·가로 잘림을 검사했다. 모델 실행 성능은 에뮬레이터 검사 범위에 포함하지 않는다.

## 시스템 키보드 버튼 영역 (0.3.5)

S26 Ultra에서 navigationBars inset이 0인 상태로 시스템 키보드 선택·숨기기 버튼이 IME 하단에 그려져 앱 도구와 겹치는 것을 실기기 화면에서 확인했다. IME 하단에 최소 48dp 시스템 버튼 영역과 8dp 간격을 확보하고 stable navigation / mandatory gesture inset이 더 크면 반영한다. 삼성의 키보드 버튼 표시 설정은 변경하지 않는다.

에뮬레이터와 S26 Ultra UI 검사, zero-inset 안전 여백 검사 및 단위 테스트를 통과했다. 실제 키보드를 표시한 S26 Ultra 화면에서도 앱 도구와 시스템 버튼이 분리된 것을 확인했다. 검증 자료: ~/.local/share/h-opentypeless/verification/ime-insets/.


## 종료·로컬 모델 안정성 (0.3.6)

PCM 녹음 종료 대기는 IME 메인 스레드에서 별도 작업자로 옮겼다. 취소/키보드 전환에서는 마이크 작업자에게 종료를 요청하고 기다리지 않는다. 네이티브 release가 끝날 때까지 기존 RecordingLease를 유지하며, 세션 세대 확인과 종료 중 임시 파일 추적으로 늦은 결과·임시 WAV 잔여를 방지한다.

실행 오류를 일시적 오류와 바이너리 호환성 오류로 구분한다. 메모리 부족·타임아웃·연결 종료·기타 처리 실패는 모델을 영구 비활성화하지 않는다. LinkageError 호환성 오류만 재검사 전까지 차단한다. 종류가 없는 이전 failure 기록은 더 이상 사용 차단 근거로 삼지 않는다. 기존 RAM/여유 메모리/온도 정책과 모델 파일 확인은 유지한다.

Whisper JNI는 UTF 문자열과 모델 컨텍스트를 RAII로 해제하고, 입력 null·배열 할당·예외 상태를 검사한다. C++ 할당 실패와 예외를 Java 오류로 전달한다. 모델 로딩 시간과 실제 추론 시간을 STT/LLM별로 기록하며 기존 PSS 표본과 함께 확인할 수 있다. 모델을 매번 종료하는 정책은 유지한다.

정적 검사에서 확인된 구형 Android API 가드와 Android 13 이상 뒤로가기 콜백도 보완했다. SDK/Gradle 최신 버전 권고 등 기존 경고는 남아 있지만 lint 오류는 없다.

40개 단위 테스트, APK/계측 APK 빌드 및 lint 통과. S26 Ultra에 설치 후 JNI 잘못된 입력200회, 지연된 종료 중 메인 스레드 취소 응답, 교정 실패 시 원문 보존 검사를 통과했다. Gemma E2B 단일 짧은 문장 검사 전체13.945초/로딩12.376초/추론1.206초, 표본 PSS최대1655MB. Whisper base는 무음 자산 로딩 검사 전체8.127초/로딩348ms/추론3814ms, 표본 PSS295MB. 무음 검사에서 텍스트를 생성했으므로 정확도 검증으로 볼 수 없다. VAD 변경은 보류했다. 이 숫자는 단일 실행이며 장시간 발열·메모리 누수·실사용 정확도의 보증이 아니다. 로그는 ~/.local/share/h-opentypeless/android-stability*.log.

모델 로딩 중 취소 검사 후 :inference 프로세스가 남지 않은 것을 확인했다. 기존 로컬/원격 화면 분리·삽입·취소 UI 회귀 검사도 통과했다. 테스트용 WAV를 삭제하고 설치된 앱0.3.6(versionCode9)을 다시 열었다. 이전 APK 백업: ~/.local/share/h-opentypeless/android-before-stability-0.3.6.apk.
